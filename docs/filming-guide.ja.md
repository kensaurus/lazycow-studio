# 撮影ガイド

Lazycow Studio がうまく編集できる素材の撮り方です。ほとんどは、スタジオがクリップを選んで切る仕組みから来ています（[どの瞬間を使うかの決め方](architecture.md#how-it-picks-which-moments-to-use)、英語）。それぞれのコツに、理由と根拠のコードを添えました。**（一般的なコツ）** と書いたものは、スタジオが確かめるわけではない、ふつうの撮影の心得です。

[English](filming-guide.md)

## まずはこれだけ

- **5〜15秒の短いカットを、たくさん。1カットに1つの被写体。** 被写体が変わったら、いったん録画を止めます。
- **カットの最初と最後は、1秒ほど止めて撮ります。**
- **横向きなら4K、縦向きなら1080p以上、30fps。** 選べるなら HDR ではなく SDR で。
- カメラやスマホの**位置情報はオンのまま**。
- **人が映らない風景**を撮るか、映る人には先に了解をもらいます。
- **動画を中心に。** 写真も使えますが、1本のリールで写真は3割までです。

## カットの長さ：5〜15秒。長回しはしない

スタジオがリールを切るときの決まりはこうです。
- リールの長さは8〜25秒です。
- 1カットは1〜4秒で、切れ目は音楽のビートに合わせた0.5秒刻みに置きます（`py/studio/reels.py` の `check_reel`、`py/studio/sound.py` の `fit_cuts`）。
- 同じファイルを1本のリールで2回使うことはありません。

撮るときに意味すること：

| 理由 | コード |
|:--|:--|
| **1つのファイルから、1本のリールに使えるのは1カットだけ。** 短いカットが20本あれば20か所を埋められますが、長回し1本では1か所です。 | `check_reel`：「a source file is used twice」で書き出しが止まります。 |
| **検索が見るのは、各ファイルの3枚の静止画だけ。** 長さの15%・50%・85%の位置の3枚を混ぜて、1つの特徴にします。15秒のカットなら、映っているものがそのまま特徴になります。20分のファイルは、7分おきの3場面を混ぜた、ぼやけた特徴になります。 | `library._keyframes`、`library._clip` |
| **カットはショットより少し長く。** 使うショットの長さ＋0.8秒以上のクリップしか選ばれず、最初と最後の0.3秒は使いません。4秒のショットなら、5秒ほどの素材が要ります。 | `assemble.py`、`pick.best_window` |
| **40秒を超えると、始めと終わりが捨てられます。** 長いファイルの最初の10%と最後の15%は使いません（ドローンの離陸と着陸とみなすため）。場面選びもキーフレームだけで行います。 | `pick.best_window` |
| **長いファイルは遅い。** 長い4Kファイルから場面を選ぶと、ほぼ全体をデコードします。エディターのプレビューも、全体を作り直します。 | `pick.picture_fit`、`server/review.mjs` の `proxyFor` |
| **一度使うと、ファイル全体の順位が下がります。** どこかのリールで使うたびに、まだ使っていない場面も含めて、そのファイルは検索で下がります。 | `assemble.rank`：リール1本につき −0.06 |

まとめると、**1カット5〜15秒、1カットに被写体か動きを1つ、長くても40秒未満**です。同じ場所を角度を変えて10カット撮れば、スタジオは10通りから選べます。2秒のカットは、たいていのショットには短すぎます。

## 1カットの中で

- **動く前と後に、1秒ほど止めます。** 最初と最後の0.3秒は使われません。スタジオはピントが合っていて、少し動きのある区間を好みます。止める・ゆっくり動く・止めるの順に撮ると、良い区間がとれます（`best_window`：シャープさ＋0.6×動き）。
- **1カットに、ゆっくり安定した動きを1つ。** パン、前に歩く、ティルトアップなど。速く振る動きや揺れは、長いファイルでは減点されます。手持ちで揺れが大きいクリップ（`SHAKE_AUTO` 0.20 以上）は、ffmpeg に vidstab があれば自動で手ぶれ補正します（`py/studio/shot.py`）。補正すると少し拡大されるので、最初から安定して撮るのがいちばんです。
- **ズームはしません。** 横向きの素材は 9:16 に切り抜かれるので、デジタルズームを重ねると画質がさらに落ちます（一般的なコツ）。
- **真っ暗・真っ白な画面は避けます。** 明るさが6%未満や96%を超える区間は減点されます（`best_window`）。
- **何かに向けて撮ります。** 地面や草のアップ、手、紙、画面は「つなぎ」とみなされ、自動では選ばれません（`library.py` の `JUNK_PROMPTS`、`JUNK_MAX` 0.4）。

## 縦と横、構図

スタジオは1本のリールを3つのサイズで書き出します。**9:16（1080×1920）、4:5（1080×1350）、16:9（1920×1080）**で、どれも30fpsです（`shared/spec.json`、`shared/channels.json`）。

| 撮り方 | 9:16 と 4:5 | 16:9 |
|:--|:--|:--|
| **横向き（16:9）** | 高さいっぱいの枠で切り抜きます。枠は顔、なければいちばんシャープな部分を追います（`shot.measure`、`crop_for`） | そのまま全体 |
| **縦向き（9:16）** | そのまま全体（4:5 は上下を切ります） | 真ん中に置き、後ろに同じ映像をぼかして敷きます |

- **リールだけなら、どちらでもかまいません。** YouTube の長い動画も作るなら、横向きで撮ります。
- **横向きでは、被写体をひとつにします。** 9:16 の枠は横幅の3分の1ほどで、被写体に寄っていきます。左右の端に別々の被写体があると、両方は入りません。
- **文字を置ける、静かな部分を残します。** 空、壁、芝生などです。文字は、各ショットの落ち着いた側に置かれます（`reels.place_words`）。9:16 で文字が入るのは画面の上から3分の2までで、下の3分の1はアプリのボタン用に空けてあります（`shared/spec.json` の `safe`）。

## 解像度・フレームレート・HDR

- **解像度。** **4Kの横向き**から 9:16 を切り抜くと、枠の幅は1215pxあり、1080pxを余裕で埋めます。**1080pの横向き**だと枠は607pxしかなく、約1.8倍に引き伸ばすので甘く見えます。横向きは**4K**で撮ります。縦向きなら1080p以上で十分です。
- **フレームレートは30fps。** すべてのショットは30fpsで書き出します（`shot.py` の `fps=30`）。60fpsでも使えます。コマを間引くので、動きが少しくっきりします。ただし、スタジオが60fpsの素材を自動でスローにすることはありません。AIのスローモーションも、31fps以下のクリップにしか使いません（`py/studio/ai.py`）。24fpsや25fpsの素材は30fpsに変換されるので、パンでカクつくことがあります（一般的なコツ）。
- **HDR。** HDR動画（HLGやPQ。iPhoneの標準「HDRビデオ」もこれです）は、色づけの前にふつうのSDRへ変換します（`py/studio/formats.py` の `TONEMAP`）。使えますが、スマホの画面で見た色やコントラストとは変わることがあります。色を思いどおりにしたいなら HDR をオフに。iPhone は「設定 › カメラ › ビデオ撮影 › HDRビデオ」、Android はたいていカメラアプリの動画設定にあります（一般的なコツ）。

## 光と色

- スマホでは**露出とピントを固定**します（被写体を長押し）。撮影中に明るさが揺れなくなります（一般的なコツ）。
- **1つの場面では、ホワイトバランスをそろえます。** スタジオはショットごとに明るさを測って色づけします。初期設定では、各ショットの色かぶりをリール全体の中央値へ半分寄せます（どの色も8%以内。`colorMatch`、`shot.py` の `color_correction`）。暖色から青へ大きく飛ぶ場面までは直せません（一般的なコツ）。
- **朝夕のゴールデンアワーと、日没後のブルーアワー。** 日の出後と日没前の1時間、日没後の30分ほどは、やわらかく暖かい光と深い空が撮れます（一般的なコツ）。暗いカットも使われます。夜かどうかは暗さで判定します（`library.py`）。
- 撮影の前に**レンズを拭きます。** 指紋の曇りは、シャープさの点数では取り返せません（一般的なコツ）。

## 音

- **クリップの音はそのまま使います。** どのリールにもクリップ本来の音だけの版があり、音楽入りの版ではクリップの音の下に音楽を沈めます（`sound.mix`）。場面選びは音を聞かないので、風の強いカットも選ばれえます。
- **風。** マイクに風防を付けるか、風の強い日は壁や車の陰から撮ります（一般的なコツ）。長い動画は風を測って、風の強いクリップの音を下げます（`quality.py`）。リールはしません。
- **無音でもかまいません。** fal.ai のキーを入れれば、音のないショットにAIで自然な音を付けられます（[AI tools](ai-api.md)、英語）。

## 場所と時刻

- **位置情報（GPS）はオンのまま。** プロジェクトには「撮影場所」を決められます（Settings › Keys & AI › This project）。リールに選ばれるのはそこで撮った素材だけで、そうでない素材は書き出しのときに止まります（`reels.py` の `off_site`）。場所は、そのファイルのGPS、同じフォルダのほかのファイルのGPS、イベントフォルダのGPS、フォルダ名の順に決めます（`library.place_from`）。GPSのないフォルダにあるGPSのないファイルは「不明」になり、自動では選ばれません。
- **GPSがないときは**、フォルダを追加するとき（Footage › Add a folder）に **Shot here**（「信頼する」モード）を選びます。中のファイルは、すべて撮影場所で撮ったものとして扱われます（`sources.add(path, "trusted")`）。撮影場所を決めていないプロジェクトは、すべての素材を使います。
- **カメラの時計を合わせておきます。** 撮影月から季節のタグが付き、日付でファイルが旅やイベントに結び付きます（`media.captured_from_name`、`library.event_of`）。

## 人と同意

- **自動で作るリールは、人を避けます。** 顔が見つかったクリップや、CLIPが「人が映っている」と判定したクリップ（後ろ姿や手も含む）は、テーマが顔を許していない限り使いません（`library.py` の `PERSON_MAX` 0.35、`assemble.py` の `noFaces`）。選ばれるのは風景、場所、料理、ものです。
- **顔が映ったリールは承認できません。** 誰かが Consent OK を押すか、**Blur faces** で書き出し直すまでです（`py/studio/review_actions.py`）。撮る前に、本人に了解をもらいましょう。
- 顔の検出には YuNet のモデルファイルが必要です。[Run it fully local](architecture.md#run-it-fully-local)（英語）を見てください。

## 写真・ドローン・360度

- **写真**は1本のリールのショットの3割まで、1枚2秒までです（`check_reel`）。スタジオが自動で作るリールは、かならず動画から始まります（`assemble.py`）。HEIC、AVIF、DNG、カメラのRAWも読めます（`shot.open_photo`）。
- **ドローン。** DJI のファイルは機器名か `DJI_` で始まるファイル名で見分け、手ぶれ補正はしません（`shot.is_drone`）。テーマによっては、ドローンの素材だけを使います。1回の長いフライトを通しで録るより、動きごとに録画を止めて撮り直します。40秒を超えるファイルは、最初の10%と最後の15%を使わないからです。
- **360度。** Insta360 や 2:1 の正距円筒の素材を見分け、切り抜く代わりに、動く仮想カメラで画角を作り直します（`py/studio/sphere.py`）。

## フォルダとファイル名

- **撮影に出た日ごとに、日付入りのフォルダを。** 素材フォルダの中に `2026\20261123_winter-open\` のように作ります。名前の日付がイベントの日付になり、フォルダが場所の判定のまとまりになります（`library.event_of`）。
- **完成した動画は、素材フォルダに置きません。** ファイル名に `_reel_`、`_9x16`、`_4x5`、`_16x9` を含むものや、`ready`・`drafts` というフォルダの中身は、完成品とみなされて素材には使われません（`ingest.is_output`）。
- **元のファイルを残します。** 同じクリップが Google フォトからの取り込みとフォルダの両方にあれば、元のファイルのほうを使います（`library.prefer_originals`）。
