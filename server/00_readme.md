# server

- Health and resilience (`health.mjs`): `/api/health` (this server's build id, whether the files on disk are newer (`stale`), the machine verdict ok / slow / blocked with one line per check and its fix, the measured seconds per reel). POST `/api/restart` hands the port to a fresh copy of the server (refused while a reel renders unless `force`); a start that finds the port busy retries for 6 s, then says whether another studio already runs. POST `/api/job/cancel` (`{slug}`) drops a queued render or stops a running one (the whole process tree). Renders and autopilot refuse to start under 3 GB free (507). The python helper failing rejects every waiting request at once and restarts on the next one. Every job view carries `eta` (seconds left, from this machine's history in `jobs.jsonl`) and `cancellable`. `/favicon.svg`.
- `review.mjs` serves http://127.0.0.1:4317 (loopback only) and keeps one `python -m studio service` helper alive so searches are instant. Every request must carry a loopback `Host` (no DNS rebinding) and a POST must come from the studio's own origin (`fromStudio`), so another website open in the browser cannot browse folders or start jobs.
  - Dashboard and flow: `/api/overview` (every reel with status, render progress, music, footage totals), POST `/api/autopilot` (one proposal per theme from the newest footage, each queued to render).
  - Render queue: one job at a time (`build` or a sound-only `remix`). Python prints `STAGE n/7` and `PROGRESS done/of` unbuffered. `/api/events` pushes each change, and the running job once a second so the clock keeps moving; `/api/job?slug=` is the same snapshot for one reel.
  - `/api/config`: the footage folder and the preview-clip folder, so the page has no machine path of its own.
  - Editing: `/api/reels`, `/api/reel?slug=`, `/api/channels`, POST `/api/library`, `/api/asset?id=`, `/api/themes`, POST `/api/assemble`, POST `/api/project` (save; `render: true` queues a build unless a rule fails), `/api/project?slug=`, POST `/api/remix`.
  - Sound: `/api/audio` (music and effects with licences), POST `/api/audio/fetch` (`{kind: music|sfx, query}`, CC0 / public domain from Openverse).
  - Library memory: POST `/api/veto` (`{id, on}`): a clip auto-made reels never pick again.
  - Covers: POST `/api/cover` (`{slug, t}`) cuts every network's cover from that moment; `/api/spec` serves `shared/spec.json` (the text-safe areas the Safe zone overlay draws).
  - YouTube: `/api/youtube` (connected? which channel), `/api/youtube/connect` → Google sign-in → `/oauth/youtube` (loopback redirect, PKCE), `/api/youtube/meta?slug=`, POST `/api/youtube/upload` (`{slug, at?, privacy?}`; runs beside the render queue and reports through `/api/events` as a `youtube` job), `/api/youtube/videos` (what is on the channel).
  - Log: `/api/log` (spend, local models, each reel's trace, finished jobs); every finished job is appended to `<data>/renders/jobs.jsonl`.
  - Footage: POST `/api/footage/scan` (catalog and tag new footage, reported as job `footage`). Folders: `/api/sources` (every footage folder, the last diff, the watcher's schedule), `/api/fs/roots` (drives on this OS), `/api/fs/list?path=` (subfolders and a media count), POST `/api/sources/discover` (`{path}`, job `discover`, its report in `result`), POST `/api/sources/add` (`{path, mode: gps|trusted}`, then a watch run), POST `/api/sources/remove`, POST `/api/sources/watch`. The watcher runs `sources watch` every `STUDIO_WATCH_MINUTES` (30; 0 = off) while no render is running. Google Photos: `/api/gphotos`, `/api/gphotos/connect` → `/oauth/gphotos`, POST `/api/gphotos/session` (returns the picker URL), `/api/gphotos/session?id=` (picked yet?), POST `/api/gphotos/import` (job `gphotos`).
  - Posting log: `/api/posts`, POST `/api/posts/plan` (`{slug, network, at}`), `/api/posts/done` (`{id, url}`), `/api/posts/drop` (`{id}`, planned only), `/api/posts/booked` and `/api/posts/link` (`{id, url?, at?}`: a booking made on the site, and its link), `/api/posts/ics?id=` (calendar reminder). `/api/drafts` lists the review records.
  - Posting from the studio: `/api/connections` (each connector, its status and the fields it asks for; secrets never returned), POST `/api/connect/start` (opens the network's own sign-in: Bluesky, Facebook), POST `/api/connect/setup` (one-time setup, e.g. the owner's Meta App ID and secret), POST `/api/publish` (`{slug, network, at?, id?}`, job `post-<slug>-<network>`; Facebook schedules on Facebook, Bluesky is queued and the server sends due posts with `publish --due` on a timer). **`/api/publish` does not check the review status itself**; the page only offers approved reels (see `docs/HANDOFF.md`).
  - Your Chrome (`helper.mjs`, `chrome-bridge.mjs`; `docs/helper.md`): POST `/api/helper/install`, POST `/api/helper/token` (the Chrome link key, saved to `.env`, never echoed), POST `/api/share` (a 15-minute local link to one channel file, for the browser to upload), POST `/api/package` (`{slug, channels}`: make missing network files). Its schedule routes refuse any reel that is not approved.
  - Words (`py/studio/wording.py`): `/api/words` (the bank with use counts and repeat totals), POST `/api/words` (`{action: add, kind, ja, en}` · `{action: status, ja, status: approved|retired}` · `{action: suggest, n?, topic?}`: AI drafts saved as "suggested"), POST `/api/words/reword` (`{slug, preview?}`: fresh approved words for one reel; saved unless `preview`). Each runs `python -m studio.wording` as its own process. `/api/overview` gives each reel `sameWords`, `sameHook`, `wordsPending` and `hookText`.
  - Networks and playbooks: POST `/api/channels/set` (`{id, on?, account?}`: a network on or off for this project), `/api/playbooks` (`shared/playbooks.json`).
  - Footage health: `/api/footage/health` (reels of fresh footage left, reuse, cameras, what to film next; cached 10 min, `?fresh=1` recounts), POST `/api/footage/cameras` (read each file's camera make and model, a job).
  - Projects (one per brand): `/api/workspaces` (GET list, POST create), POST `/api/workspaces/edit`, `/api/workspaces/forget` (files stay), `/api/workspaces/switch` (restarts on that project).
  - YouTube app: `/api/youtube/app` (GET the Google app in use, POST your own client JSON), POST `/api/youtube/disconnect`. `/api/about`: the licence and credit texts.
  - Research (Firecrawl, read-only; shapes in `docs/research-api.md`): `/api/research` (key present?, credits, cache, today's requests), POST `/api/research/ideas` (`{topic?, days?}`), `/api/research/site-check` (`{url?}`), `/api/research/page` (`{url}`), `/api/research/events` (`{days?}`), `/api/research/links`; each takes `fresh: true`. Each runs `python -m studio.research` as its own process with a timeout (never the footage helper). POST `/api/settings` also takes `{firecrawl_key}`: checked with Firecrawl's free credit call, upserted into `.env`, never echoed.
  - AI assist (shapes in `docs/ai-api.md`): GET `/api/ai` (keys present as booleans, caps, spend per reel / total / today), POST `/api/ai/estimate` (`{slug, tools, options?}`), POST `/api/ai/run` (same + `render`; a job `ai-<slug>` beside the render queue, refused with 402 `cap` before anything runs), GET `/api/ai/review?slug=` (the last review, free), POST `/api/ai/review` (`{slug, fresh?}`, runs the reviewer). POST `/api/settings` also takes `{fal_key, openrouter_key, together_key}` (checked free, upserted into `.env`, never echoed, `""` removes) and `{ai_reel_cap_usd, ai_total_cap_usd}`. `/api/reel` carries `ai`, `aiLabel`, `aiLabelNote`.
  - Live work: `/api/jobs` (every job queued, running, or ended in the last 6 hours: renders, AI touches and scoring, posting and swaps, footage checks, picking footage; the page's board re-reads it on reconnect and every 15 s, and the `/api/events` stream updates it in between). Running progress is sent at most every 200 ms per job.
  - Older words on bookings: `/api/posts/stale` (each booking made before its reel got new words, and why it is not swapped yet: ready, review, rendering, soon, elsewhere), POST `/api/posts/autoreplace` (`{on}`). While on (the default), a 5-minute timer swaps one ready booking at a time at the same slot (`publish --replace`, or the Chrome helper for X and TikTok); YouTube at most 5 a day. State in `<home>/auto-replace.json`.
  - Scores and predictions (`py/studio/predict.py`): `/api/perf/scores` (0-100 per reel from the AI review's hook and look, a fresh headline and a fitting length), `/api/perf/predictions` (every booking's frozen 80 % range against its actual result, coverage, rank correlation), POST `/api/perf/score-all` (one job, `score-all`, that runs the AI review on every rendered reel without one).
  - Dropped files: POST `/api/footage/upload?name=` (a streamed file dragged onto the page; photo and video types, 8 GB, saved under `<data>/imports/collected/<date>_dropped/` by `dropbox.mjs`'s `saveUpload`, catalogued 20 s after the last one).
  - AI balances: `/api/ai/credits` (per provider: studio spend and what the provider reports left; cached 10 min, `?fresh=1`).
  - Make reels: POST `/api/autopilot` makes one theme per helper call and queues each render as soon as its reel exists; the batch is a job (`make-…`) on the board.
  - Files: `/proxy?id=` (540p edit preview), `/file?p=` (studio, audio and media folders only, Range for seeking), POST approve / consent / reject / re-roll through `python -m studio`.
- `mcp.mjs` (`npm run mcp`): an MCP server over stdio so AI agents (Claude Code, Claude Desktop, Cursor) can drive the studio. A thin client of the HTTP API above (POSTs carry the studio Origin); `publish_reel` refuses any reel whose review status is not "approved", and there is no approve tool. Setup: `docs/mcp.md`.
- Posting gates: `/api/publish`, `/api/youtube/upload` and `/api/helper/post` answer 409 for a reel that is not approved, and the jobs check again (`publish.assert_approved`). The Chrome helper's **schedule** routes refuse too. Request trust (Host, Origin, cross-site GETs, body size, slugs that cannot become options) lives in `trust.mjs`.
- `editor.html` is the whole interface (vanilla JS, English / 日本語 through `I18N` and `tr()`), served fresh from disk, so a change shows after a page reload with no server restart.
  - **Six sections** in the top bar (`SECTIONS`; a section with two pages shows them as tabs): **Reels** (`#/`: cards grouped by kind, stage or week, 14 a group; filters by state; **Make reels**; **Approve all**, which skips house reels and ticks Consent OK where faces are on camera), **Footage** (`#/footage`: footage health, then the library and the folder picker), **Ideas** (`#/ideas`: Firecrawl research, read-only), **Posting** (`#/posting` with tabs Schedule, All reels and Sent, plus **Plan posts**; `#/youtube`), **Results** (`#/results`: per-network numbers and suggestions; `#/log`: activity log), **Settings** (`#/accounts`, `#/keys`). Search is Ctrl K; **System** is the machine check.
  - **Plan posts** (`plannerPlan`): one post per network per day, each waiting approved reel once, LinkedIn and LINE about weekly, no faces on Google Maps, and never beyond a site's days-ahead limit (`CHROME_NETS`, `BOOK_AHEAD`). Facebook and Bluesky go through `/api/publish`; X, TikTok, Google Maps, LINE and LinkedIn through the Chrome helper.
  - **Editor** (`#/reel/<slug>`): CapCut-style. Under the player: Safe zone overlay and Use as cover. Exports: Download, Copy text, Remind me / Mark posted per network, and the YouTube schedule box. Library, Audio (listen, use, find more CC0 tracks, effects on/off, Apply sound), In reel, Exports; player; properties; timeline with text, video, music, effects and the rendered mix; magnetic main track, snapping, split, trim, undo. Drag the panel dividers to resize (remembered; double-click resets). The header's review queue steps through reels waiting for review; Approve and Reject move on to the next.

Rules that block a render: a repeated source, photos over 30% or over 2 s, cuts off the 0.5 s grid, shots over 4 s, length outside 8-25 s, no hook in the first 0.5 s, words not ending with the picture, a file not placed at the ranch, a finished edit used as footage, or copy the fact guard rejects. Approve is blocked while faces are on camera without consent, unless **Blur faces** was on for that render.

## dropbox.mjs

The drop box for Footage › Collect footage: a second small server on port 4319 (`STUDIO_DROP_PORT`) that runs only while
the owner has it open. One page and one upload route under `/d/<secret>`, private-network addresses only, photo and
video types only, 8 GB a file, 5 GB of disk always left free, names that cannot leave `<data>/imports/collected/`.
Tests: `test/dropbox.test.mjs`.
